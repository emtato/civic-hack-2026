# Proviso submission video

Draft 01: **2 minutes 32 seconds, 1920 × 1080, 30 fps**. Remotion 4.0.543.

The draft uses the app's cream, green and copper palette, local Manrope and DM Sans fonts, animated typography, moving app close-ups and an original ambient music sketch. It has no voiceover. Timing will be adjusted around the team's recorded narration.

## Preview and export

From this directory:

```sh
npm ci
npm run dev
npm run lint
npm run render
```

Open the `Proviso-Draft` composition. The current preview is available at `http://localhost:3000/Proviso-Draft` while Studio is running. The export is `out/proviso-draft-v1.mp4`. Exports, browser binaries and dependencies are ignored by Git.

`npm run render:opening` exports the first 20 seconds for quick style reviews. `npm run music` regenerates the original music bed using Python's standard library. Set `music` to false in Studio's composition props for a silent preview.

## Capture provenance and limitations

The JPEGs in `public/captures/` show the actual frontend, captured against a **separate video-only staging API**, not the live database. They are animated still captures, not continuous footage of a production session.

The local app API was unavailable during capture. To avoid changing application data, `scripts/fixture-server.mjs` serves the existing three-proposal fixtures from `frontend/src/data/proposals.ts` and uses the existing `applyFeedbackToAggregate` function for a memory-only response. A fictional `demo-resident` session is used solely on the staging frontend. No real account, password, AI service, municipal submission or database write is involved.

The response moves the fictional total from 45 to 46 participants and 39 to 40 conditions. Both versions of the pickup-hours comparison are fictional. The app interface's generic wording about an official notice is part of the captured UI; the surrounding video explicitly labels this example as staged. These captures do **not** establish current consultation status, live persistence, actual source-change detection or municipal adoption.

To restage captures, use two terminals:

```sh
# Terminal 1, video directory
npm run capture:api

# Terminal 2, frontend directory
VITE_API_BASE_URL=http://127.0.0.1:8011 npm run dev -- --port=5174 --strictPort
```

Browse `http://localhost:5174`. The fixture API binds only to loopback; its login accepts fictional video-only values and is not an authentication implementation. Do not deploy it. Restart it to reset all staged data.

Before submission, capture the final verified app workflow, replace draft/staging labels as appropriate, verify the actual source/limitations statements, record narration and create corrected captions. Keep the exported submission below three minutes and test viewing access.
